# Native SDK packaging and licensing

The CMake `package` target creates a platform SDK containing the WIMF library,
`wimf_c.h`, exported `WIMF::wimf` package configuration, `wimf-native` when
enabled, and both required license texts.

```bash
cmake -S . -B build-sdk -DCMAKE_BUILD_TYPE=Release -DBUILD_SHARED_LIBS=ON
cmake --build build-sdk --config Release
cmake --build build-sdk --config Release --target package
```

WIMF is GPL-3.0-or-later. Applications distributing WIMF or a derivative must
comply with that license, including corresponding-source obligations where
applicable. The bundled Zstandard 1.5.7 code uses its upstream BSD license,
included separately as `Zstandard-LICENSE`. This page is engineering guidance,
not legal advice; distributors remain responsible for their compliance.

Release archives should be generated by CI from a tagged source revision, retain
their SHA-256 manifest, and use GitHub artifact attestations before being called
signed or provenance-verified. Ordinary CI artifacts are test packages and must
not be represented as official releases.

Windows native archives are prepared for SignPath signing. The workflow remains
dormant until the project is accepted and the protected `signpath` environment
contains its assigned organization, project, policy, artifact-configuration,
and API-token values. See [`CODE_SIGNING.md`](../CODE_SIGNING.md). Never place a
certificate or private key in the repository or GitHub Actions secrets; SignPath
retains signing keys in its signing service.
